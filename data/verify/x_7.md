### item Userverfault-559834
Type: unanswerable
Question: With Apache's mod_bw, how can I limit files over 1MB to 200kb/s?
Reference answer: Use LargeFileLimit * 1024 204800 inside the mod_bw block; files over 1024 KB are limited to 204800 bytes per second.
Evidence chunk ids: []
Source (NOT in the index):
How to limit connection speed
I figured this out using LargeFileLimit:
<IfModule mod_bw.c>
BandwidthModule On
ForceBandWidthModule On
Bandwidth all "52428800"
MaxConnection all "400"
LargeFileLimit * 1024 204800
BandWidthError 510
</IfModule>
This will mean that the domain is limited to 50mb bandwidth (52428800), that it can only have 400 connections at once and that any files over 1mb will be limited to 200kb/s (204800).
How to limit connection speed
For anyone reading this later you can also put an extension instead of * to limit just zips,rars,avis or whatever.

Reference answer: dd if=/dev/urandom of=/dev/sda bs=1000k, after shutting down as many services as possible (especially the windowing system).
Evidence chunk ids: []
Source (NOT in the index):
Best way to self destruct all data on a linux server?
I endorse all the other recommendations for DBAN, but if you really can't do this, I've had a lot of success with shutting down as many services as I can (esp. the windowing system), then doing
dd if=/dev/urandom of=/dev/sda bs=1000k
from a root shell prompt, sitting back, and waiting. This basically writes pseudorandom bytes, a megabyte at a time, all over /dev/sda (you may need to use /dev/hda or other device as appropriate to your setup).
Best way to self destruct all data on a linux server?
Because the kernel and the tool are in-core, the system will stay up for a surprising amount of time while this is running, and it leaves an utterly unbootable and mostly-completely-scrambled system behind it.

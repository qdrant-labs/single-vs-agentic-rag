Reference answer: It uses the client's MAC address (chaddr) as the link-layer destination and the offered address (yiaddr) as the IP destination, since delivery happens at layer 2.
Reference evidence:
[chunk 979199] How can a DHCP OFFER message be unicast?
While an address of 0.0.0.0 can be used as a source address for DHCP, it shouldn't be used as a destination address on the network. [chunk 979201] How can a DHCP OFFER message be unicast?
The IP destination address (in the IP header) is set to the BOOTP
'yiaddr' address and the link-layer destination address is set to
the BOOTP 'chaddr' address.
Unfortunately, some client
implementations are unable to receive such unicast IP datagrams
until they know their own IP address (thus we have a "chicken and
egg" issue).

System answer: The DHCP server can send its reply directly to the client's MAC address, which is all it knows about the client at that point, instead of broadcasting it.

### judge item 01e87e13
Question: Two distros share one swap partition. What must be done to the swap space at boot for sharing to work, and why is hibernating one install and then booting the other dangerous?
Reference answer: The swap must be initialized at boot; hibernating one OS while running another risks data loss because changing any disk filesystem between suspend and resume corrupts the hibernated system's state.
Reference evidence:
[chunk 283521] Are there any side effects when two distros share a swap partition?
It's possible. In fact, you can share the swap space between completely different operating systems, as long as you initialize the swap space when you boot. It used to be relatively common to share swap space between Linux and Windows, back when it represented a significant portion of your hard disk.
Two restrictions come to mind:
The OSes cannot be running concurrently (which you might want to do with virtual machines).
You can't hibernate one of the OSes while you run another.
[chunk 391258] How will hibernation work in two Linux installations sharing a swap partition?
Only one OS is allowed to mount a filesystem at a time, and with Hibernation, the system is "still running". If you Hibernate, then boot in another OS, change filesystems, then reboot and resume the Hibernated OS that still remembers the old state of those modified filesystem... it all goes ka-boom.
* BIG FAT WARNING
********************************************************* 
* 
* If you touch anything on disk between suspend and resume... 
* ...kiss your data goodbye.

System answer: The swap space must be initialized (re-created) at every boot. Hibernating one install and booting the other is dangerous because the first system's memory image is stored in swap: the second system will either try to resume from the first's data and crash, or erase it so the first cannot be resumed, and it can corrupt filesystems the hibernated system still has mounted.

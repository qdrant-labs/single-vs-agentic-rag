Question: On a Red Hat-style system, installing a package fails saying it conflicts with another version of that same package, though none is listed as installed. What is the likely cause?
Reference answer: A previous installation aborted and left files behind; the installer refuses if any file already exists and attributes the conflict to the same package.
Reference evidence:
[chunk 315648] How can a version of a package conflict with itself?
This kind of error messages can appear if you try to install a package whose previous installation got aborted without completing.
rpm by default won't install a package if any of the file it needs to install already exists in the filesystem.
So, if a previous installation aborted and some files were left behind, all succesive attempt will fail.

Question: Why is installing Proxmox on top of an existing Ubuntu server a bad idea?
Reference answer: Proxmox runs on Debian; the dependency chain would force replacing almost every Ubuntu package with Debian ones, leaving a badly broken, mostly-Debian Ubuntu install.
